# map-LAIpot

**온실 화분작물 per-pot LAI 추정 트랙** — lingbot-map 3D 재건 + 잎 세그 + 화분별 분리

> `map-LAIcrop`(노지/군락, **수직 nadir** 촬영, 지면평면 기준)과 **별도 트랙**.
> 여기는 **온실 + 화분(베드 위) + 가로 이동 촬영** 가정.

---

## 왜 별도 트랙인가

| | map-LAIcrop | **map-LAIpot** |
|---|---|---|
| 촬영 | 수직(nadir) | **가로 이동** (필요 시 약간 위) |
| 대상 | 노지 군락 | **베드 위 화분작물** (단차·이중단차) |
| 기준 | 단일 지면 평면 | **up 벡터 + 화분별 footprint** |
| LAI 분모 | 지면/캐노피 면적 | **화분 footprint (per-pot)** |

---

## 핵심 설계 결정

**1. "지면 평면"이 아니라 "up 벡터"만 필요하다.**
직접법 면적은 평면 **높이(offset d)에 무관**하고 **법선(normal)에만** 의존한다(투영이 법선 ⊥ u,v 기저로 이뤄져 d가 상쇄). 따라서 floor/베드/화분 흙 중 무엇에 평면을 잡든 결과가 같다 → **단차/이중단차는 면적을 망치지 않는다.** 필요한 건 **중력 up 방향 하나**.

**2. 진짜 리스크는 normal(방향)과 분모(정의).**
- 가로 촬영 + 클러터(벽/베드 측면/화분 옆면) → 일반 RANSAC이 **수직면에 꽂혀 normal이 틀어짐**. → tilt 제약 RANSAC으로 해결.
- 여러 화분이 한 convex hull로 묶이면 분모가 부풀어 LAI 과소 → **화분/개체별 분리** 필수.

**3. 분모 = 화분 footprint (per-pot LAI).** 식재밀도 기반 "재배면적당"은 추후 옵션(미정).

## 파이프라인 (단계별)

```
가로 이동 촬영 시퀀스
        │
        ▼
  lingbot-map 3D 재건  (공유: 코드 수정 없이)
  world_points / conf / images
        │
        ▼
  잎 세그멘테이션  (공유: map-LAIcrop/segmentation 재사용 예정)
  leaf_masks
        │
        ▼
┌──────────────────────────────┐
│ Stage 1  up_vector.py        │  중력 up 벡터 robust 추정
│  tilt 제약 RANSAC + PCA 재적합│  (벽/화분옆면 기각, 베드 상판 채택)
└──────────────────────────────┘
        │
        ▼
┌──────────────────────────────┐
│ Stage 2  pots.py (예정)      │  화분/개체 분리
│  up 투영 2D footprint 클러스터링│  (DBSCAN/연결요소) → 개체별 점군
└──────────────────────────────┘
        │
        ▼
┌──────────────────────────────┐
│ Stage 3  lai_pot.py (예정)   │  개체별 LAI
│  잎 silhouette 면적 ÷ 화분면적 │  → per-pot LAI + 분포
└──────────────────────────────┘
        │
        ▼
  pot_lai_result.json / per_pot_points.npy
```

---

## 한계 (정직하게)

모델은 **캐노피 표면만** 본다(잎 사이를 못 뚫음) → silhouette 면적은 다층 잎을 과소추정.
따라서 결과는 진짜 다층 LAI가 아니라 **"표면 기반 유효 LAI"**로 라벨링한다. 추후 다시점 누적/보정계수로 개선 여지.
